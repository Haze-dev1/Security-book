## Route 53

A **public hosted zone** per domain (≈$0.50/month plus queries); the registrar's NS records point at the four name servers AWS assigns (Part II chapter 7's delegation lesson). Records:

- **Alias records** to AWS resources (ALB, NLB, CloudFront, S3 website, API Gateway, another record in the zone): work at the apex, follow the target's changing IPs, queries to aliases of AWS resources are free. Use them for everything AWS-hosted.
- **CNAME** for external targets (SaaS vendors' verification, email providers).
- **TXT** for domain verification (ACM uses CNAME), SPF/DKIM/DMARC for email.
- **CAA** restricting issuance to `amazon.com` (ACM) and any other CA you use.
- **Private hosted zones** associated with VPCs for internal names (`db.prod.client.internal` → RDS endpoint CNAME) so applications reference stable names, not endpoint hostnames in config.

**Health checks** (HTTP/HTTPS/TCP from multiple AWS locations, or calculated/CloudWatch-alarm based) drive **failover routing** (primary/secondary records), and feed CloudWatch alarms as an external uptime signal. **Routing policies**: simple, weighted (gradual migrations, A/B), latency-based (multi-Region), geolocation/geoproximity (residency, localisation), failover, multivalue (crude client-side balancing). Low TTLs (60 s) on records that participate in failover or migrations.

Route 53 **Resolver** answers DNS inside VPCs (the `.2` address); Resolver endpoints and rules forward between on-premises and VPC resolvers for hybrid names. **Resolver DNS Firewall** blocks resolution of malicious domains; **query logging** records what your VPC asked for.

```hcl
resource "aws_route53_record" "api" {
  zone_id = aws_route53_zone.main.zone_id
  name    = "api.client.com"
  type    = "A"
  alias { name = aws_lb.main.dns_name, zone_id = aws_lb.main.zone_id, evaluate_target_health = true }
}
resource "aws_route53_record" "api_v6" { zone_id = aws_route53_zone.main.zone_id, name = "api.client.com", type = "AAAA", alias { name = aws_lb.main.dns_name, zone_id = aws_lb.main.zone_id, evaluate_target_health = true } }
```

## Application Load Balancer

```hcl
resource "aws_lb" "main" {
  name               = "client-a-prod"
  load_balancer_type = "application"
  internal           = false
  subnets            = module.vpc.public_subnets
  security_groups    = [aws_security_group.alb.id]
  ip_address_type    = "dualstack"
  idle_timeout       = 60
  drop_invalid_header_fields = true
  enable_deletion_protection = true
  access_logs { bucket = aws_s3_bucket.alb_logs.id, prefix = "client-a-prod", enabled = true }
}

resource "aws_lb_listener" "http" {          # redirect everything to HTTPS
  load_balancer_arn = aws_lb.main.arn
  port = 80; protocol = "HTTP"
  default_action { type = "redirect", redirect { port = "443", protocol = "HTTPS", status_code = "HTTP_301" } }
}

resource "aws_lb_listener" "https" {
  load_balancer_arn = aws_lb.main.arn
  port = 443; protocol = "HTTPS"
  ssl_policy        = "ELBSecurityPolicy-TLS13-1-2-2021-06"
  certificate_arn   = aws_acm_certificate.api.arn
  default_action { type = "fixed-response", fixed_response { content_type = "text/plain", message_body = "not found", status_code = "404" } }
}

resource "aws_lb_listener_rule" "api" {
  listener_arn = aws_lb_listener.https.arn
  priority     = 100
  condition { host_header { values = ["api.client.com"] } }
  action { type = "forward", target_group_arn = aws_lb_target_group.api.arn }
}

resource "aws_lb_target_group" "api" {
  name        = "client-a-prod-api"
  port        = 8000
  protocol    = "HTTP"
  target_type = "ip"                            # Fargate tasks; "instance" for ASG instances
  vpc_id      = module.vpc.vpc_id
  deregistration_delay = 20
  load_balancing_algorithm_type = "least_outstanding_requests"
  health_check { path = "/health/ready", interval = 10, timeout = 5, healthy_threshold = 2, unhealthy_threshold = 2, matcher = "200" }
}
```

Points from Part II chapter 13 made concrete: a default fixed 404 so unknown hosts get nothing; host-based rules so one ALB serves several hostnames (add more rules and target groups, or an authenticate-oidc action for admin hosts); dualstack for IPv6 clients; access logs for diagnosis; deletion protection; `drop_invalid_header_fields` against header smuggling. Additional certificates attach via SNI (`aws_lb_listener_certificate`). WAF associates with the ALB (chapter 12) when CloudFront is not in front.

### When to add an NLB

Non-HTTP protocols, static IPs for partner allow-lists (NLB with EIPs → ALB target group for HTTP services), extreme connection rates, or TLS passthrough for mTLS to the application. Otherwise the ALB alone is simpler.

## CloudFront

```hcl
resource "aws_cloudfront_distribution" "app" {
  enabled             = true
  aliases             = ["app.client.com"]
  default_root_object = "index.html"
  price_class         = "PriceClass_100"             # NA+EU edges only: cheaper; use All for global audiences
  http_version        = "http2and3"
  is_ipv6_enabled     = true
  web_acl_id          = aws_wafv2_web_acl.cf.arn    # WAF scope CLOUDFRONT (us-east-1)

  origin {
    origin_id                = "s3-frontend"
    domain_name              = aws_s3_bucket.frontend.bucket_regional_domain_name
    origin_access_control_id = aws_cloudfront_origin_access_control.frontend.id
  }
  origin {
    origin_id   = "alb-api"
    domain_name = aws_lb.main.dns_name
    custom_origin_config { http_port = 80, https_port = 443, origin_protocol_policy = "https-only", origin_ssl_protocols = ["TLSv1.2"] }
    custom_header { name = "X-Origin-Verify", value = var.origin_secret }   # ALB rule requires it: blocks direct ALB access bypassing CloudFront/WAF
  }

  default_cache_behavior {                             # SPA shell and assets
    target_origin_id       = "s3-frontend"
    viewer_protocol_policy = "redirect-to-https"
    allowed_methods        = ["GET", "HEAD", "OPTIONS"]
    cached_methods         = ["GET", "HEAD"]
    cache_policy_id        = data.aws_cloudfront_cache_policy.caching_optimized.id
    response_headers_policy_id = aws_cloudfront_response_headers_policy.security.id
    compress               = true
    function_association { event_type = "viewer-request", function_arn = aws_cloudfront_function.spa_rewrite.arn }
  }
  ordered_cache_behavior {                             # API: no caching, forward everything
    path_pattern             = "/api/*"
    target_origin_id         = "alb-api"
    viewer_protocol_policy   = "https-only"
    allowed_methods          = ["GET", "HEAD", "OPTIONS", "PUT", "POST", "PATCH", "DELETE"]
    cached_methods           = ["GET", "HEAD"]
    cache_policy_id          = data.aws_cloudfront_cache_policy.caching_disabled.id
    origin_request_policy_id = data.aws_cloudfront_origin_request_policy.all_viewer.id
  }
  custom_error_response { error_code = 403, response_code = 200, response_page_path = "/index.html", error_caching_min_ttl = 0 }   # alternative SPA handling
  viewer_certificate { acm_certificate_arn = aws_acm_certificate.cf.arn, ssl_support_method = "sni-only", minimum_protocol_version = "TLSv1.2_2021" }   # cert in us-east-1
  restrictions { geo_restriction { restriction_type = "none" } }
  logging_config { bucket = aws_s3_bucket.cf_logs.bucket_domain_name, prefix = "app" }
}
```

Serving the API through CloudFront too (same origin as the SPA, `/api/*` behaviour) eliminates CORS, gives the API HTTP/3 and edge TLS, and puts WAF and Shield in front of it; the `X-Origin-Verify` header plus an ALB listener rule rejecting requests without it stops attackers bypassing CloudFront by hitting the ALB directly. Part II chapter 17 covers caching discipline; the API behaviour must have caching disabled.

## ACM

Request certificates in the **same Region as the ALB** and separately in **us-east-1 for CloudFront**; validate via DNS (Terraform's `aws_acm_certificate_validation` with Route 53 records automates it); include every SAN you need (`api.client.com`, `*.client.com`); keep the validation CNAME in place forever (renewal re-validates); monitor `DaysToExpiry`. ACM certificates cannot be exported for use on EC2 (use ACME there, Part V chapter 8) unless issued by **ACM Private CA** for internal names (monthly fee per CA; worth it for mTLS or many internal services).

## Operations

Alarms: ALB `HTTPCode_ELB_5XX_Count`, `HTTPCode_Target_5XX_Count`, `TargetResponseTime` p99, `UnHealthyHostCount`, `RejectedConnectionCount`; CloudFront `5xxErrorRate`, `OriginLatency`; Route 53 health check status; ACM `DaysToExpiry`. Logs: ALB access logs (Athena table), CloudFront standard or real-time logs. Changes: ALB listener rules and CloudFront behaviours in IaC; CloudFront deployments take minutes to propagate; invalidate `/index.html` on frontend deploys (chapter 16).

## Common mistakes

- Certificate for CloudFront requested outside us-east-1.
- Pointing DNS at ALB IPs or at CloudFront with an A record instead of an alias.
- No default 404 action; unknown hosts hit the first target group.
- ALB reachable directly when CloudFront+WAF was meant to be the only path.
- Target group health check on `/` with a redirect; targets flap.
- Deregistration delay at 300 s; slow deploys.
- Forgetting dualstack and AAAA records.
- `PriceClass_100` for a global audience, or All for a regional one (cost/latency mismatch).
- Deleting the ACM validation record; renewal fails a year later.
