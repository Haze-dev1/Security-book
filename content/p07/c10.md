# Storage: S3, EBS and EFS

:::objectives
- Choose between object, block and file storage for each kind of data and understand their durability, consistency and cost models.
- Configure S3 buckets for production: access control, encryption, versioning, lifecycle, replication, logging and performance.
- Manage EBS volumes and snapshots for instances and self-managed databases.
- Use EFS where shared POSIX storage is genuinely required.
:::

Default guidance: **S3 for everything that can be an object** (which is most things), **EBS only for OS and self-managed stateful software**, **EFS only when several hosts must share POSIX files**. Managed databases (chapter 11) remove most EBS management from your life.

## S3 in production

```hcl
resource "aws_s3_bucket" "uploads" { bucket = "client-a-prod-uploads-${data.aws_caller_identity.current.account_id}" }   # globally unique names: include the account ID

resource "aws_s3_bucket_public_access_block" "uploads" {
  bucket = aws_s3_bucket.uploads.id
  block_public_acls = true; block_public_policy = true; ignore_public_acls = true; restrict_public_buckets = true
}
resource "aws_s3_bucket_ownership_controls" "uploads" { bucket = aws_s3_bucket.uploads.id; rule { object_ownership = "BucketOwnerEnforced" } }   # disables ACLs entirely
resource "aws_s3_bucket_server_side_encryption_configuration" "uploads" {
  bucket = aws_s3_bucket.uploads.id
  rule { apply_server_side_encryption_by_default { sse_algorithm = "aws:kms", kms_master_key_id = aws_kms_key.data.arn }, bucket_key_enabled = true }
}
resource "aws_s3_bucket_versioning" "uploads" { bucket = aws_s3_bucket.uploads.id; versioning_configuration { status = "Enabled" } }
resource "aws_s3_bucket_lifecycle_configuration" "uploads" {
  bucket = aws_s3_bucket.uploads.id
  rule { id = "abort-incomplete-multipart"; status = "Enabled"; filter {}; abort_incomplete_multipart_upload { days_after_initiation = 7 } }
  rule { id = "expire-old-versions"; status = "Enabled"; filter {}; noncurrent_version_expiration { noncurrent_days = 90 } }
  rule { id = "tier-cold-data"; status = "Enabled"; filter { prefix = "exports/" }; transition { days = 30, storage_class = "STANDARD_IA" }; transition { days = 180, storage_class = "GLACIER_IR" } }
  rule { id = "expire-tmp"; status = "Enabled"; filter { prefix = "tmp/" }; expiration { days = 1 } }
}
resource "aws_s3_bucket_logging" "uploads" { bucket = aws_s3_bucket.uploads.id; target_bucket = aws_s3_bucket.access_logs.id; target_prefix = "uploads/" }
resource "aws_s3_bucket_policy" "uploads" {
  bucket = aws_s3_bucket.uploads.id
  policy = jsonencode({
    Version = "2012-10-17",
    Statement = [
      { Sid = "DenyInsecureTransport", Effect = "Deny", Principal = "*", Action = "s3:*", Resource = [aws_s3_bucket.uploads.arn, "${aws_s3_bucket.uploads.arn}/*"], Condition = { Bool = { "aws:SecureTransport" = "false" } } },
      { Sid = "DenyUnencryptedPuts", Effect = "Deny", Principal = "*", Action = "s3:PutObject", Resource = "${aws_s3_bucket.uploads.arn}/*", Condition = { StringNotEquals = { "s3:x-amz-server-side-encryption" = "aws:kms" } } },
      { Sid = "AppRoleAccess", Effect = "Allow", Principal = { AWS = aws_iam_role.api_task.arn }, Action = ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"], Resource = "${aws_s3_bucket.uploads.arn}/*" }
    ]
  })
}
```

What each piece does: **Block Public Access** (also at the account level) makes public exposure impossible; **BucketOwnerEnforced** disables the legacy ACL system; **SSE-KMS with a bucket key** encrypts with your key at low KMS cost (SSE-S3 is the free default if you do not need key-level control); **versioning** protects against overwrite and deletion (pair with lifecycle to expire old versions and with MFA Delete or Object Lock for critical data); **lifecycle rules** control cost (incomplete multipart cleanup is the one everyone forgets); **access logging** or CloudTrail data events for audit; the **bucket policy** denies plaintext transport and unencrypted uploads and grants the application role exactly what it needs.

Storage classes: Standard (hot), Intelligent-Tiering (automatic, small monitoring fee, good default for unknown access patterns), Standard-IA and One Zone-IA (infrequent, retrieval fee), Glacier Instant/Flexible/Deep Archive (archival; minutes to hours retrieval, minimum storage durations). Lifecycle transitions move objects down the ladder.

**Replication** (same-Region or cross-Region) copies new objects to another bucket (and account) for DR, compliance or latency; existing objects via Batch Replication. **Object Lock** (WORM) for immutability (backups, audit logs). **S3 Event Notifications** → SQS/Lambda/EventBridge trigger processing on upload (Part III chapter 9). **Presigned URLs** for client uploads/downloads. **Access Points** simplify per-application access to shared buckets. **Storage Lens** and **Inventory** show what you have and what it costs.

Performance: thousands of requests per second per prefix with automatic scaling; multipart uploads for objects over 100 MB; byte-range GETs for partial reads; Transfer Acceleration for distant uploaders; CloudFront in front for public reads (Part II chapter 17). Costs: storage, requests (PUT/LIST are pricier than GET), data transfer out, retrieval fees for cold classes; lifecycle and the gateway endpoint (chapter 6) are your levers.

Static website hosting: do not use the S3 website endpoint (HTTP only, requires public bucket); use CloudFront + OAC with a private bucket (chapter 9).

## EBS

Volume types: **gp3** (default: 3,000 IOPS/125 MB/s baseline, independently provisionable up to 16,000/1,000), **io2 Block Express** (consistent high IOPS, sub-ms, for demanding databases), **st1/sc1** (throughput-optimised/cold HDD for sequential big data), **gp2** (legacy; migrate to gp3 for lower cost and consistent performance). Volumes are AZ-bound; attach to one instance (io2 multi-attach exists for clustered filesystems). Encryption via KMS: enable **EBS encryption by default** at the account/Region level so every volume and snapshot is encrypted without thinking.

**Snapshots** are incremental, stored in S3 (durable, multi-AZ), crash-consistent (Part V chapter 6), and the basis of AMIs. Automate with **Data Lifecycle Manager** or **AWS Backup** (schedules, retention, cross-Region/account copies, Vault Lock). Restore by creating a volume from the snapshot in the target AZ. Fast Snapshot Restore pre-warms for immediate full performance at a cost. Delete orphaned volumes (unattached, from terminated instances with `delete_on_termination = false`) and snapshot sprawl; both are classic silent costs (chapter 4).

Operations: resize online (volume modify, then grow the filesystem, Part V chapter 6); monitor `VolumeQueueLength`, `BurstBalance` (gp2), throughput versus the instance's EBS bandwidth cap (small instances cap EBS throughput regardless of volume type); use **EBS-optimised** instances (default on current generations).

## EFS

A managed NFSv4 filesystem spanning AZs, mounted by many EC2 instances, ECS tasks (including Fargate via volume configuration) and EKS pods (EFS CSI). Use when an application genuinely needs a shared POSIX filesystem (legacy CMS uploads directories, shared build caches, certain ML pipelines, home directories); otherwise S3 is cheaper and more scalable. Modes: Standard (multi-AZ) or One Zone; throughput **Elastic** (pay for what you use; the modern default), Bursting, or Provisioned; **Infrequent Access** lifecycle to cut cost for cold files. Security: mount targets in private subnets with a security group allowing 2049 from clients, encryption at rest and in transit (TLS via the EFS mount helper), **access points** per application with enforced POSIX user and root directory, IAM authorisation for mounts. Backups via AWS Backup. Performance: per-operation latency is higher than EBS; metadata-heavy workloads (millions of small files, `ls` on huge directories) suffer; measure before committing.

## Choosing, by data type

| Data | Store |
|---|---|
| User uploads, generated documents, media | S3 (private, presigned, lifecycle) + CloudFront for delivery |
| Static frontend | S3 + CloudFront with OAC |
| Database data (self-managed) | EBS gp3/io2 on a dedicated volume; better: RDS |
| Backups, exports, logs, audit archives | S3 with lifecycle, versioning, Object Lock where needed, replication for DR |
| Container images, build artifacts | ECR / S3 |
| Shared files across instances | EFS (or redesign to S3) |
| Scratch / cache | Instance store, tmpfs, or EBS gp3 |
| Data lake / analytics | S3 (Parquet) + Athena/Glue |

## Common mistakes

- Public buckets; ACLs still enabled; policies with `Principal: *` and no condition (Part IV chapter 24).
- No lifecycle rules; incomplete multipart uploads and old versions billing forever.
- Deleting versioned objects and expecting space back (delete markers; expire noncurrent versions).
- S3 website endpoints instead of CloudFront + OAC.
- Databases on gp2; small instances starving EBS throughput.
- Unencrypted volumes/snapshots because default encryption was never enabled.
- Orphaned EBS volumes and snapshots.
- EFS for a workload that should be S3; surprise cost and latency.
- Bucket names without an account/environment qualifier; name collisions and accidental cross-environment access.

## Exercises

1. Create the production uploads bucket in Terraform with every control above; try to upload an unencrypted object and to apply a public policy; confirm both fail.
2. Enable EBS default encryption; create a volume, snapshot it, copy the snapshot to another Region, and restore from it.
3. Run S3 Storage Lens (or an inventory) on an account; identify incomplete multipart uploads, old versions and unused buckets; add lifecycle rules and measure the saving.
