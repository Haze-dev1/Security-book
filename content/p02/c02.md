## Why models

Networking is too complex to reason about all at once. Models divide it into layers with defined responsibilities and interfaces, so you can change one (swap Wi-Fi for Ethernet, HTTP/1.1 for HTTP/2) without touching the others. For an engineer the real value is diagnostic: a problem lives at one layer, and the tools and fixes differ completely per layer. "It does not work" becomes "DNS resolves, TCP connects, TLS fails with certificate error", which is a two-minute fix instead of a two-hour hunt.

## The OSI model

Seven layers, defined by the ISO in the 1980s. Nobody implements it literally, but everyone uses its numbering.

## The TCP/IP model

The Internet's actual architecture uses four layers: **Link** (OSI 1–2), **Internet** (OSI 3), **Transport** (OSI 4), **Application** (OSI 5–7). When engineers say "Layer 4" or "Layer 7" they are using OSI numbers to talk about TCP/IP layers; the mixing is universal and harmless.

| TCP/IP layer | OSI layers | Unit of data | Addressing | Devices |
|---|---|---|---|---|
| Application | 5–7 | message | URL, hostname | proxies, ALB, WAF |
| Transport | 4 | segment (TCP) / datagram (UDP) | port | NLB, firewalls (ports) |
| Internet | 3 | packet | IP address | routers, NACLs |
| Link | 1–2 | frame | MAC address | switches, NICs |

## Encapsulation and decapsulation

Sending: the application hands a message to the transport layer, which adds a TCP header (making a segment); IP adds its header (packet); the link layer adds a frame header and trailer. Receiving reverses it. Each layer only reads its own header and passes the payload up. This is why:

- A router can forward your HTTPS traffic without any ability to read it: it stops at Layer 3.
- A security group can allow "TCP 443" without knowing whether the content is HTTP/1.1 or HTTP/2: it stops at Layer 4.
- An ALB can route `/api/*` to one target group and `/static/*` to another: it decapsulates all the way to Layer 7, which requires terminating TLS (it must decrypt to read the path).
- An NLB cannot route by path; it forwards TCP connections and is therefore faster, simpler and can pass TLS through untouched.

That last contrast is the single most practically important consequence of layering for deployments, and chapter 13 builds on it.

## Vocabulary decoded

- **L4 load balancer / proxy**: forwards TCP/UDP connections by IP and port. Fast, protocol-agnostic, preserves end-to-end TLS. AWS NLB, HAProxy TCP mode, IPVS.
- **L7 load balancer / proxy**: understands HTTP. Routes by host, path, header; terminates TLS; can add headers, retry, rate limit, authenticate. AWS ALB, Nginx, Envoy, Traefik, Caddy.
- **L3/L4 firewall**: filters by IP and port (security groups, NACLs, iptables). **L7 firewall / WAF**: inspects HTTP for attack patterns (AWS WAF, ModSecurity).
- **SNI** (Server Name Indication): the hostname sent in clear text during the TLS handshake so one IP can host many certificates. Sits at Layer 6 but is visible to Layer 4 devices, which is how an NLB with TLS passthrough can still route by hostname.
- **MTU / fragmentation**: a Layer 3 concern. VPNs and tunnels reduce the effective MTU; symptoms are connections that open but hang when transferring data.
- **Keep-alive**: exists at two layers. TCP keep-alive (L4) probes an idle connection; HTTP keep-alive (L7) reuses one TCP connection for several requests. They are unrelated and both matter.

## Where the model breaks down

Real systems blur the layers. TLS sits awkwardly between 4 and 7. QUIC merges transport and encryption into one UDP-based protocol. Middleboxes inspect layers they "should not" (deep packet inspection, TLS interception on corporate networks). Service meshes do Layer 7 routing on behalf of Layer 4-unaware applications. Do not treat the model as law; treat it as a vocabulary and a diagnostic ladder.

## Common mistakes

- Debugging at Layer 7 (restarting the app, reading application logs) when the failure is at Layer 3 or 4 (security group, route table).
- Expecting an NLB to route by URL path, or expecting an ALB to pass through client certificates untouched.
- Treating "ping fails" as "host is down" when ICMP is simply blocked.
- Confusing TCP keep-alive with HTTP keep-alive when tuning idle timeouts.
- Allowing "all traffic" at Layer 4 because the application "handles security at Layer 7".
