## First principles: why code, not clicks

A console is excellent for learning and terrible for operating. Infrastructure created by hand has no history (who changed the security group and why?), no review, no reproducibility (staging and production drift apart within weeks), no disaster recovery story (rebuilding from memory under pressure), and no way to test a change before it hits production. **Infrastructure as code (IaC)** moves infrastructure into the same workflow as application code: files in git, pull requests, automated plans showing exactly what will change, applies by a pipeline with an audit trail, and the ability to recreate an entire environment from scratch.

Two paradigms exist. **Declarative** tools (Terraform/OpenTofu, CloudFormation, Pulumi, CDK) describe the desired end state and compute the changes needed; **imperative** scripts (shell with the AWS CLI) describe steps and must handle every current state themselves. Declarative wins for infrastructure because the tool handles the diff, dependency ordering and idempotency.

## Terraform's model

Terraform reads `.tf` files describing **resources** (things to create), **data sources** (things to look up), **variables** (inputs), **outputs** (exports) and **providers** (plugins for AWS, Cloudflare, GitHub, Kubernetes, Datadog and hundreds more). It records what it created in **state**. Each run **refreshes** state against reality, computes a **plan** (create, update in place, destroy and recreate) and **applies** it.

## A first real configuration

@file: envs/staging/main.tf
```hcl
terraform {
  required_version = "~> 1.9"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.80"
    }
  }

  backend "s3" {
    bucket       = "acme-tfstate-123456789012"
    key          = "portal/staging/terraform.tfstate"
    region       = "eu-west-1"
    encrypt      = true
    use_lockfile = true           # S3-native locking (Terraform >= 1.10); older: dynamodb_table
  }
}

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project     = "portal"
      Environment = var.environment
      ManagedBy   = "terraform"
      Owner       = "platform@acme.example"
    }
  }
}

module "network" {
  source      = "../../modules/network"
  name        = "portal-${var.environment}"
  cidr        = "10.20.0.0/16"
  az_count    = 2
  nat_gateways = 1                # staging: one NAT to save cost; production: one per AZ
}

module "database" {
  source             = "../../modules/postgres"
  name               = "portal-${var.environment}"
  subnet_ids         = module.network.private_subnet_ids
  allowed_sg_ids     = [module.app.service_security_group_id]
  instance_class     = "db.t4g.small"
  multi_az           = false       # production: true
  deletion_protection = true
  backup_retention_days = 7
}

module "app" {
  source            = "../../modules/ecs-service"
  name              = "portal-${var.environment}"
  vpc_id            = module.network.vpc_id
  subnet_ids        = module.network.private_subnet_ids
  public_subnet_ids = module.network.public_subnet_ids
  image             = var.image            # passed by the pipeline: registry/portal@sha256:...
  desired_count     = 1
  cpu               = 512
  memory            = 1024
  environment = {
    APP_ENV = var.environment
  }
  secrets = {
    DATABASE_URL = module.database.connection_secret_arn
  }
}

output "alb_dns_name" {
  value = module.app.alb_dns_name
}
```

@file: envs/staging/variables.tf
```hcl
variable "region" {
  type    = string
  default = "eu-west-1"
}

variable "environment" {
  type = string
  validation {
    condition     = contains(["dev", "staging", "production"], var.environment)
    error_message = "environment must be dev, staging or production."
  }
}

variable "image" {
  type        = string
  description = "Container image reference, pinned by digest."
  validation {
    condition     = can(regex("@sha256:[0-9a-f]{64}$", var.image))
    error_message = "image must be pinned by digest."
  }
}
```

## Modules: the unit of reuse

A **module** is a directory of Terraform files with inputs and outputs. Root modules (one per environment) compose child modules (`network`, `postgres`, `ecs-service`) that encode your organisation's standards once: encryption on, logging on, tags required, sensible defaults. Environments differ in variable values, not in resource definitions.

@file: modules/postgres/main.tf (excerpt)
```hcl
resource "aws_db_instance" "this" {
  identifier                 = var.name
  engine                     = "postgres"
  engine_version             = var.engine_version
  instance_class             = var.instance_class
  allocated_storage          = var.allocated_storage
  max_allocated_storage      = var.allocated_storage * 4
  storage_encrypted          = true
  kms_key_id                 = var.kms_key_arn
  db_subnet_group_name       = aws_db_subnet_group.this.name
  vpc_security_group_ids     = [aws_security_group.db.id]
  multi_az                   = var.multi_az
  backup_retention_period    = var.backup_retention_days
  deletion_protection        = var.deletion_protection
  skip_final_snapshot        = false
  final_snapshot_identifier  = "${var.name}-final"
  performance_insights_enabled = true
  manage_master_user_password = true     # credentials created and rotated in Secrets Manager
  username                   = "app_admin"
  apply_immediately          = false

  lifecycle {
    prevent_destroy = true               # a plan that would destroy this fails loudly
    ignore_changes  = [engine_version]   # minor upgrades applied by AWS maintenance, not by plan churn
  }
}

resource "aws_security_group_rule" "from_app" {
  for_each                 = toset(var.allowed_sg_ids)
  type                     = "ingress"
  security_group_id        = aws_security_group.db.id
  from_port                = 5432
  to_port                  = 5432
  protocol                 = "tcp"
  source_security_group_id = each.value
}
```

Module design rules: small, opinionated inputs with validation; outputs for everything consumers need (IDs, ARNs, security group IDs); no provider blocks inside child modules; semantic-versioned and published (git tags or a registry) when shared across repositories; a README with examples; tests (`terraform test`) for the invariants you care about.

## Language essentials

- **Expressions and functions**: string interpolation, `for` expressions, conditionals (`var.multi_az ? 2 : 1`), `try`, `coalesce`, `lookup`, `jsonencode`, `templatefile`.
- **`count` versus `for_each`**: prefer `for_each` keyed by stable strings; `count` indices shift when you remove an element, causing destroy-and-recreate of the wrong resources.
- **`depends_on`**: explicit dependencies when Terraform cannot infer them (IAM propagation, for example). Use sparingly.
- **`lifecycle`**: `prevent_destroy`, `create_before_destroy` (for resources referenced by others, such as launch templates and certificates), `ignore_changes`, `replace_triggered_by`.
- **Data sources**: look up AMIs, existing VPCs, account IDs, availability zones; make configurations portable across accounts.
- **Locals**: computed values shared within a module.
- **`moved` and `import` blocks**: refactor without destroying (rename a resource address) and adopt existing infrastructure into state declaratively.

## Workflow and hygiene

```checklist
# Terraform change hygiene
- terraform fmt and terraform validate pass locally and in CI
- Providers and modules pinned (~> for providers, exact tags for modules); lockfile committed
- A plan is produced on the pull request and read by a reviewer, especially any -/+ lines
- Apply uses the saved plan from the reviewed commit, from CI, never from a laptop
- State lives in a remote, encrypted, versioned, locked backend; nobody edits it by hand
- Secrets are not in .tf files or tfvars committed to git
- Resources that hold data carry prevent_destroy and deletion protection
- Every resource gets default tags including owner and environment
- Drift detection runs on a schedule (plan with no changes expected) and alerts
```

## OpenTofu and alternatives

OpenTofu is the open-source fork of Terraform (after the 2023 licence change), compatible with the same configurations and providers for most purposes; organisations choose based on licence posture and feature needs (OpenTofu added state encryption early). Pulumi and the AWS CDK express infrastructure in general-purpose languages with loops and types, which suits teams who prefer code over HCL; CloudFormation is AWS-native and covered in the next chapter. The concepts in this chapter apply to all of them.

## Common mistakes

- Running `apply` from laptops with personal credentials; the audit trail disappears and state conflicts appear.
- Treating `terraform destroy` as harmless in an environment that shares state with something important.
- Giant single root module for everything: slow plans, huge blast radius, everyone blocked on one lock.
- Copy-pasting environments instead of using modules with variables.
- Hardcoding account IDs, AMI IDs and ARNs instead of data sources and variables.
- Ignoring `-/+` in a plan and recreating a database.

## Exercises

1. Write a `network` module (VPC, subnets, route tables, NAT) with validated inputs and outputs; use it from two root modules (staging, production) with different sizing.
2. Introduce drift by changing a security group in the console; run a plan, explain the diff, and decide whether to revert reality or adopt the change in code.
3. Rename a resource using a `moved` block and confirm the plan shows no destroy.
