# Insecure Deserialization and Mass Assignment

:::objectives
- Explain why deserializing untrusted data with formats that encode types or behaviour leads to code execution, and which formats and libraries are dangerous.
- Design data interchange with plain, schema-validated formats.
- Prevent mass assignment by binding requests to explicit input models rather than to database models.
- Recognise related trust-the-client bugs: hidden fields, client-side totals, ID substitution in nested objects.
:::

## Insecure deserialization

Serialization turns objects into bytes; deserialization turns bytes back into objects. Some formats encode not just *data* but *which class to instantiate and how*: Python `pickle`, Java native serialization, PHP `unserialize`, Ruby `Marshal`, .NET `BinaryFormatter`, YAML with arbitrary tags (`yaml.load` without a safe loader), and some JSON libraries configured with polymorphic type handling (Jackson's default typing). Deserializing attacker-controlled bytes in these formats means letting the attacker choose which code runs during reconstruction. Gadget chains in common libraries turn that into arbitrary command execution.

:::vulnerable
```python
import pickle, base64
@app.post("/session/restore")
def restore(body: dict):
    state = pickle.loads(base64.b64decode(body["blob"]))      # attacker crafts a pickle whose __reduce__ runs os.system
    return {"restored": state}
```

```python
import yaml
config = yaml.load(user_supplied_text)                          # PyYAML < 6 default loader instantiates arbitrary Python objects via !!python/object tags
```
:::

:::secure
```python
import json
from pydantic import BaseModel

class SessionState(BaseModel):
    model_config = ConfigDict(extra="forbid")
    cart: list[CartItem]
    locale: str = Field(pattern=r"^[a-z]{2}(-[A-Z]{2})?$")

@app.post("/session/restore")
def restore(body: SessionState):                                 # JSON parsed to plain data, then validated into a known shape
    return {"restored": body.model_dump()}

config = yaml.safe_load(user_supplied_text)                     # only plain scalars, lists and maps
```
:::

Rules:

1. **Never deserialize untrusted input with a format that can instantiate arbitrary types.** Pickle, Java serialization, `Marshal`, `BinaryFormatter`, unsafe YAML loaders and polymorphic JSON typing are for trusted, internal, same-version data at most, and even then prefer alternatives.
2. **Use plain data formats** (JSON, protobuf, MessagePack without type extensions, CBOR) and **validate into explicit schemas** before use.
3. **If a dangerous format is unavoidable** (legacy systems, caches), authenticate the bytes first: HMAC the serialized blob with a server secret and verify before deserializing, so only data you produced is ever deserialized. Still treat it as a liability to remove.
4. **Keep deserialization libraries patched**; many of the worst vulnerabilities in enterprise software were gadget chains in widely used Java libraries.
5. **Watch the indirect paths**: session cookies containing serialized objects (Rails and some Java frameworks historically), cache entries, message queue payloads, file formats (uploaded documents parsed by libraries with object models), and `eval`-style parsing (`eval(json)` in old JavaScript).

Related: **XML external entities (XXE)**. XML parsers that resolve external entities turn an uploaded document into file disclosure or SSRF (`<!ENTITY xxe SYSTEM "file:///etc/passwd">`). Disable DTD processing and external entities in every XML parser (`defusedxml` in Python; `XMLConstants.FEATURE_SECURE_PROCESSING` and disabling `external-general-entities` in Java). SAML, SOAP, SVG and Office formats are XML.

## Mass assignment

Frameworks make it easy to take a request body and write its fields straight onto a model: `User(**request.json)`, `user.update(request.body)`, `Model.create(req.body)`. If the model has fields the user should not control (`is_admin`, `role`, `balance`, `tenant_id`, `email_verified`, `owner_id`), the client simply includes them.

:::vulnerable
```python
@app.patch("/me")
async def update_me(request: Request, user=Depends(current_user)):
    data = await request.json()
    for k, v in data.items():                 # {"name": "Ana", "is_admin": true, "tenant_id": "t_1"}
        setattr(user, k, v)
    await user.save()
```

```javascript
// Express + Mongoose
app.patch('/me', async (req, res) => { await User.findByIdAndUpdate(req.user.id, req.body); });
```
:::

:::secure
```python
class ProfileUpdate(BaseModel):
    model_config = ConfigDict(extra="forbid")          # unknown fields rejected, not ignored
    name: str | None = Field(default=None, max_length=100)
    locale: str | None = Field(default=None, pattern=r"^[a-z]{2}(-[A-Z]{2})?$")
    marketing_opt_in: bool | None = None

@app.patch("/me")
async def update_me(body: ProfileUpdate, user=Depends(current_user)):
    changes = body.model_dump(exclude_unset=True)       # only the fields the client sent, all of them allowed
    await users.update(user.id, **changes)
```

```javascript
const ProfileUpdate = z.object({ name: z.string().max(100).optional(), locale: z.string().regex(/^[a-z]{2}(-[A-Z]{2})?$/).optional() }).strict();
app.patch('/me', async (req, res) => { const data = ProfileUpdate.parse(req.body); await User.updateOne({ _id: req.user.id }, { $set: data }); });
```
:::

Design rules:

- **Separate input models from domain models.** The input model is an explicit allow-list of fields a client may set for *this operation* and *this role*. Admin endpoints get their own input models.
- **Reject unknown fields** (`extra="forbid"`, `.strict()`), or at least ignore them explicitly; silently binding is the bug.
- **Server-set fields are set by the server**: `owner_id`, `tenant_id`, `created_at`, `status` transitions, prices and totals. They come from the session and the database, never from the body.
- **Nested objects count**: `{"order": {"items": [...], "customer": {"id": "cus_other"}}}` can reassign relationships; validate IDs in nested payloads against the caller's scope.
- **ORM conveniences are dangerous by default**: Rails `permit`, Laravel `$fillable`/`$guarded`, Django `fields` on ModelForms, Spring `@JsonIgnoreProperties`/DTOs; use them, and prefer DTOs to annotations on domain entities.

## Other "trust the client" bugs

The same instinct that produces mass assignment produces:

- **Client-computed totals**: the cart total, the discount, the price per item sent by the client and charged as-is. Recompute everything from server-side catalogue data.
- **Hidden fields and disabled inputs**: `<input type="hidden" name="user_id">`; anything in the form is editable.
- **State transitions from the client**: `status: "shipped"` in a PATCH from a customer. Expose intents (`/orders/{id}/cancel`) and validate transitions server-side.
- **Quantity and bounds**: negative quantities producing refunds, enormous quantities overflowing. Validate ranges.
- **Role claims in requests**: `role: admin` in a signup body or an unverified token.
- **GraphQL mutations with broad input types** exposing fields the resolver never intended to be settable.

## Testing

- Send extra fields (`is_admin`, `role`, `tenant_id`, `owner_id`, `balance`) in every create/update request; expect 422 (forbid) or no effect (ignore), never a change.
- Attempt nested ID substitution.
- Fuzz deserialization endpoints with malformed and type-confused payloads (strings where objects are expected and vice versa).
- Grep for `pickle.loads`, `yaml.load(` without `Loader=SafeLoader`, `ObjectInputStream`, `unserialize(`, `Marshal.load`, `enableDefaultTyping`, `eval(`.
- Review every model-binding call (`**data`, `update(body)`, `create(req.body)`) for an input schema.

## Common mistakes

- Pickle or native serialization for caches, sessions or queue messages that touch untrusted data.
- `yaml.load` without a safe loader on config contributed by users or tenants.
- XML parsers with default (unsafe) settings.
- `Model(**request.json)` convenience in CRUD endpoints.
- Ignoring unknown fields instead of rejecting them, then adding a sensitive column later that becomes silently settable.
- Trusting totals and statuses from the client.
- Admin and user endpoints sharing one input model.

## Exercises

1. In a sandbox, craft a pickle payload that executes a harmless command on load; demonstrate it against a vulnerable endpoint, then replace the format with validated JSON.
2. Audit every create/update endpoint in a service for mass assignment: send privileged fields and record which endpoints accept them. Fix with input models.
3. Configure your XML parser (for any XML you accept, including SAML and SVG) to disable external entities, and write a test with an XXE payload.
