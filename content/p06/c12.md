## The problem

A production service needs a Deployment, Service, Ingress, ConfigMap, Secret references, ServiceAccount, HPA, PDB and maybe NetworkPolicy: ten YAML files that differ slightly per environment (replicas, hostnames, resource sizes) and must be applied and upgraded as a unit. Copy-pasting manifests per environment drifts; `sed` scripts rot. [[helm]] packages manifests as a **chart** with templates and a **values** file, installs them as a named **release** tracked in the cluster, and upgrades or rolls back the whole set atomically.

## Concepts

- **Chart**: a directory (`Chart.yaml`, `values.yaml`, `templates/`) or a packaged `.tgz`, versioned (chart version) and declaring the app version.
- **Values**: parameters with defaults in `values.yaml`, overridden per environment (`-f values-prod.yaml`, `--set key=value`).
- **Templates**: Go templates rendering Kubernetes manifests from values and built-in objects (`.Release.Name`, `.Chart.Version`).
- **Release**: an installed instance of a chart in a namespace, with revision history stored as Secrets in the cluster.
- **Repository / OCI registry**: where charts are published (ECR supports OCI charts).

## A chart for your application

```
charts/app/
  Chart.yaml
  values.yaml
  values-staging.yaml
  values-prod.yaml
  templates/
    _helpers.tpl
    deployment.yaml
    service.yaml
    ingress.yaml
    serviceaccount.yaml
    hpa.yaml
    pdb.yaml
    configmap.yaml
    externalsecret.yaml
    NOTES.txt
```

```yaml
@file: Chart.yaml
apiVersion: v2
name: app
description: Client App API
type: application
version: 1.8.0            # chart version: bump on any template/default change
appVersion: "2.4.0"       # the application version (informational; the image tag comes from values)
```

```yaml
@file: values.yaml (defaults; environment files override)
image:
  repository: 123456789012.dkr.ecr.eu-west-1.amazonaws.com/client/app
  tag: ""                 # REQUIRED at deploy time: set to the immutable build tag/digest
replicaCount: 3
resources:
  requests: { cpu: 250m, memory: 512Mi }
  limits: { memory: 512Mi }
autoscaling: { enabled: true, minReplicas: 3, maxReplicas: 30, targetCPUUtilizationPercentage: 60 }
pdb: { enabled: true, minAvailable: 2 }
ingress:
  enabled: true
  className: alb
  host: ""                # per environment
  certificateArn: ""
  group: prod-shared
serviceAccount:
  create: true
  annotations: {}         # eks.amazonaws.com/role-arn for IRSA, per environment
config:
  LOG_LEVEL: info
  ENV: prod
externalSecrets:
  enabled: true
  store: aws-secretsmanager
  secretKey: prod/app/db
probes: { readinessPath: /health/ready, livenessPath: /health/live }
```

```yaml
@file: templates/deployment.yaml (excerpt)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "app.fullname" . }}
  labels: {{- include "app.labels" . | nindent 4 }}
spec:
  {{- if not .Values.autoscaling.enabled }}
  replicas: {{ .Values.replicaCount }}
  {{- end }}
  selector:
    matchLabels: {{- include "app.selectorLabels" . | nindent 6 }}
  strategy: { type: RollingUpdate, rollingUpdate: { maxSurge: 1, maxUnavailable: 0 } }
  template:
    metadata:
      labels: {{- include "app.selectorLabels" . | nindent 8 }}
      annotations:
        checksum/config: {{ include (print $.Template.BasePath "/configmap.yaml") . | sha256sum }}   # roll pods on config change
    spec:
      serviceAccountName: {{ include "app.serviceAccountName" . }}
      securityContext: { runAsNonRoot: true, runAsUser: 10001, fsGroup: 10001, seccompProfile: { type: RuntimeDefault } }
      containers:
        - name: api
          image: "{{ .Values.image.repository }}:{{ required "image.tag is required" .Values.image.tag }}"
          envFrom: [{ configMapRef: { name: {{ include "app.fullname" . }} } }]
          env:
            - { name: DATABASE_URL, valueFrom: { secretKeyRef: { name: {{ include "app.fullname" . }}-db, key: url } } }
          resources: {{- toYaml .Values.resources | nindent 12 }}
          readinessProbe: { httpGet: { path: {{ .Values.probes.readinessPath }}, port: http }, periodSeconds: 5 }
          livenessProbe:  { httpGet: { path: {{ .Values.probes.livenessPath }},  port: http }, periodSeconds: 10 }
          securityContext: { allowPrivilegeEscalation: false, readOnlyRootFilesystem: true, capabilities: { drop: [ALL] } }
```

Practices embedded: `required` for the image tag (no accidental `latest`); the config checksum annotation; HPA-aware replica handling; helpers for consistent labels; security context baked in so every environment inherits it.

```bash
helm lint charts/app
helm template app charts/app -f charts/app/values-prod.yaml --set image.tag=3f9a1c4 | kubeconform -strict   # render and validate offline
helm upgrade --install app charts/app -n prod --create-namespace \
     -f charts/app/values-prod.yaml --set image.tag=3f9a1c4 \
     --atomic --wait --timeout 10m                     # roll back automatically if the rollout fails
helm history app -n prod
helm rollback app 7 -n prod
helm diff upgrade app charts/app -f values-prod.yaml --set image.tag=NEW -n prod    # plugin: see the change before applying
```

`--atomic --wait` is the production invocation: Helm waits for the Deployment to become ready (respecting probes) and reverts the release on failure or timeout. Combine with `kubectl rollout status` in CI for explicit confirmation.

## Consuming third-party charts

Most platform components ship as charts: ingress controllers, cert-manager, external-dns, Prometheus stack, External Secrets Operator, Argo CD. Rules:

- **Pin chart versions** in your deployment repository (`helm upgrade … --version 4.11.2`, or in an umbrella chart's `Chart.yaml` dependencies with exact versions); never float.
- **Read the values** before installing; defaults are often permissive (cluster-wide RBAC, public LoadBalancers) or undersized.
- **Keep your overrides in Git**; treat chart upgrades like dependency upgrades (changelog, staging first).
- **Prefer OCI registries** or well-known repositories; verify provenance where charts are signed; mirror charts you depend on into your own registry for air-gapped or reliability reasons.
- **Render and review**: `helm template` to see exactly what will be applied; scan rendered manifests with policy tools (kube-score, Polaris, Checkov) in CI.

## Helm and GitOps

Helm is imperative by itself (`helm upgrade` from a CI job). With **Argo CD** or **Flux**, you declare "this chart, this version, these values" in Git and the controller reconciles the cluster continuously, with drift detection, a UI showing sync status, and rollback by Git revert. The pattern most mature teams use: application charts in the application repository, environment values and platform charts in a deployment repository, Argo CD or Flux applying them. CI builds images and updates the image tag in the deployment repository (a commit, often automated); the GitOps controller deploys. The audit trail is Git.

## Alternatives and complements

- **Kustomize** (built into kubectl): overlays patching base manifests per environment; no templating language, no release tracking; simpler for teams that dislike templates. Often used *with* Helm (render a chart, then patch with Kustomize).
- **Plain manifests with GitOps**: viable for small numbers of services.
- **CDK8s, Pulumi, Jsonnet**: generate manifests from real programming languages.
- **Operators**: for complex stateful software, prefer an operator (CloudNativePG, Strimzi) over a chart that merely installs it.

## Common mistakes

- Floating chart versions and image tags.
- Secrets in `values.yaml` committed to Git (use External Secrets or SOPS-encrypted values files).
- Installing without reading defaults; a public LoadBalancer or cluster-admin RBAC appears.
- Templating logic so complex the chart is unreadable; keep charts boring and push complexity to values validation (`values.schema.json`).
- Forgetting the config checksum; config changes without pod restarts.
- `helm upgrade` without `--atomic`/`--wait`; CI passes, pods crash.
- Manual `kubectl edit` on Helm-managed resources; the next upgrade reverts it (or fails on conflict).

1. Write a chart for an application with the structure above, including `values.schema.json` to make `image.tag` and `ingress.host` required. Lint, template and validate it offline.
2. Install it with `--atomic --wait`, then deploy a broken image tag and watch Helm roll back automatically.
