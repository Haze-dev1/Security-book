# Project 3: Dockerized Application

:::objectives
- Containerise the Project 2 backend with a hardened multi-stage image, run the full stack with Docker Compose including a reverse proxy, and verify image security, resource limits, secrets handling and graceful shutdown.
- Produce a signed image with an SBOM from a CI pipeline, ready for Project 4.
:::

:::prereq
Part VI chapters 1–7; Part X chapters 2–4; the Project 2 codebase.
:::

:::cost Estimated cost
Zero locally. GitHub Actions minutes within the free tier for a public repository; a private repository may use paid minutes.
:::

## Steps

### 1. The Dockerfile

```dockerfile
# syntax=docker/dockerfile:1.7
ARG PY=python:3.12.7-slim-bookworm@sha256:REPLACE_WITH_DIGEST
FROM ${PY} AS build
WORKDIR /app
ENV PIP_NO_CACHE_DIR=1 PIP_DISABLE_PIP_VERSION_CHECK=1
COPY requirements.lock ./
RUN --mount=type=cache,target=/root/.cache/pip python -m venv /venv && /venv/bin/pip install --require-hashes -r requirements.lock
COPY src/ ./src/
COPY migrations/ ./migrations/
COPY config/ ./config/

FROM gcr.io/distroless/python3-debian12:nonroot@sha256:REPLACE_WITH_DIGEST AS runtime
WORKDIR /app
ENV PYTHONUNBUFFERED=1 PATH="/venv/bin:$PATH" PYTHONPATH=/app/src
COPY --from=build /venv /venv
COPY --from=build /app /app
USER nonroot:nonroot
EXPOSE 8080
LABEL org.opencontainers.image.source="https://github.com/you/portal-api"
ENTRYPOINT ["/venv/bin/python", "-m", "app"]
```

Check `.dockerignore` excludes `.git`, `.env*`, `tests/`, `*.md`, local volumes. Build and inspect:

```bash
docker build -t portal-api:dev .
docker image inspect portal-api:dev --format '{{.Config.User}} {{.Size}}'
docker run --rm portal-api:dev --help 2>&1 | head -2          # confirms entrypoint works as nonroot
dive portal-api:dev                                            # layer inspection (optional)
```

### 2. Compose with production-like settings

```yaml
# docker-compose.yml (excerpt)
services:
  api:
    image: portal-api:dev
    build: .
    read_only: true
    tmpfs: [/tmp]
    security_opt: [no-new-privileges:true]
    cap_drop: [ALL]
    user: "65532:65532"
    environment:
      APP_ENV: production
      DATABASE_URL_FILE: /run/secrets/database_url
      REDIS_URL: redis://redis:6379/0
      OTEL_EXPORTER_OTLP_ENDPOINT: http://otel-collector:4317
    secrets: [database_url]
    deploy:
      resources:
        limits: { cpus: "0.5", memory: 512M }
    healthcheck:
      test: ["CMD", "/venv/bin/python", "-c", "import urllib.request,sys; sys.exit(0 if urllib.request.urlopen('http://127.0.0.1:8080/health', timeout=2).status==200 else 1)"]
      interval: 10s
      timeout: 3s
      retries: 3
      start_period: 15s
    depends_on:
      postgres: { condition: service_healthy }
      redis: { condition: service_started }
    networks: [internal]
    stop_grace_period: 30s

  worker:
    image: portal-api:dev
    command: ["-m", "app.worker"]
    <<: *api_hardening      # YAML anchor repeating the hardening block
    networks: [internal]

  postgres:
    image: postgres:16.4@sha256:REPLACE_WITH_DIGEST
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/postgres_password
      POSTGRES_DB: appdb
    secrets: [postgres_password]
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck: { test: ["CMD-SHELL", "pg_isready -U postgres"], interval: 5s, retries: 10 }
    networks: [internal]

  caddy:
    image: caddy:2.8@sha256:REPLACE_WITH_DIGEST
    ports: ["443:443", "80:80"]
    volumes: [./Caddyfile:/etc/caddy/Caddyfile:ro, caddy_data:/data]
    networks: [internal, edge]

secrets:
  database_url: { file: ./secrets/database_url }        # gitignored; in production, from the orchestrator's secret store
  postgres_password: { file: ./secrets/postgres_password }
networks:
  internal: { internal: true }
  edge: {}
volumes: { pgdata: {}, caddy_data: {} }
```

The application reads `DATABASE_URL_FILE` and loads the value from the file (Project 2's config loader gains `*_FILE` support). The `internal` network has no outbound route; only Caddy sits on `edge`.

### 3. Graceful shutdown

Confirm the app handles `SIGTERM`: fails readiness, stops accepting, finishes in-flight requests, closes pools, exits within `stop_grace_period`. Test: run a slow request, `docker compose stop api`, confirm the request completes and the exit code is 0.

### 4. CI pipeline

Add `.github/workflows/build.yml` from Part X chapter 2: build with BuildKit cache, Trivy scan (fail on critical/high fixable), push to GHCR tagged `sha-<sha>`, cosign keyless sign, SBOM and provenance attestations, `hadolint` on the Dockerfile. Add a `verify` job that pulls by digest and runs `cosign verify` plus a smoke test in a container.

### 5. Migrations as a one-off container

```bash
docker compose run --rm --no-deps -e DATABASE_URL_FILE=/run/secrets/migrate_url api -m app.migrate up
```

The migration uses a different credential (owner role) from the runtime (`app_rw`); in Compose, a second secret file.

## Verification

```checklist
# Project 3 verification
- Image runs as UID 65532, has no shell (docker run --rm -it portal-api:dev sh fails), and is under ~150 MB
- Trivy reports zero critical/high fixable vulnerabilities; hadolint passes
- cosign verify succeeds for the pushed digest with the expected workflow identity; SBOM attestation present
- With read_only and cap_drop ALL, the app serves requests and writes only to /tmp and its state volume
- The api container cannot reach the internet (docker compose exec api python -c "import urllib.request; urllib.request.urlopen('https://example.com', timeout=3)" fails)
- Only ports 80/443 are published on the host (docker compose ps)
- Secrets are not visible in docker inspect environment; they are files in /run/secrets
- Stopping api during a slow request lets it complete and exits 0 within the grace period
- The healthcheck turns unhealthy within 30 s when the app is wedged (simulate by stopping postgres and checking /ready-based health if you wired it so)
- Memory limit enforced: a deliberate allocation bomb is OOM-killed and restarted, not the host
```

## Security checks

Run `docker scout cves` or Trivy against the final image and the base image separately to see what the base contributes. Run Dockle or `docker-bench-security` for configuration checks. Confirm no secrets in image layers (`docker history --no-trunc`, and scan the image filesystem with gitleaks). Confirm the Compose file does not mount the Docker socket anywhere.

## Troubleshooting

- **Distroless debugging**: use `docker run --rm -it --entrypoint=/busybox/sh gcr.io/distroless/python3-debian12:debug` variants for troubleshooting only, never in production.
- **Permission denied writing files**: read-only root; write to `/tmp` (tmpfs) or a mounted volume owned by 65532.
- **Healthcheck always unhealthy**: no `curl` in distroless; use the Python one-liner or a tiny health binary.
- **Cannot resolve service names**: containers must share a network; `internal: true` networks still provide DNS between members.
- **Build cache misses in CI**: ensure the lockfile is copied before source and cache-to/from are configured.

## Cleanup

`docker compose down -v --remove-orphans`; delete test images from GHCR or set a retention policy.
