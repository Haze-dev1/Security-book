# Project 4: AWS Production Deployment

:::objectives
- Deploy the containerised backend to AWS with Terraform: VPC, ECS Fargate behind an ALB, RDS PostgreSQL Multi-AZ, ElastiCache, Secrets Manager, CloudFront with WAF, CloudWatch alarms, budgets and a CI/CD pipeline with OIDC and blue-green rollback.
- Operate it: deploy, roll back, restore, rotate, and review cost; then destroy it cleanly.
:::

:::prereq
Part VII (all), Part X (all), the Project 3 image. An AWS account you own (a sandbox, never a client's), a domain in Route 53, and the AWS CLI configured with short-lived credentials via IAM Identity Center.
:::

:::cost Estimated cost
Roughly 250–350 USD per month if left running: ALB (~20), NAT Gateway (~35 + data), Fargate 2 × 0.5 vCPU/1 GB (~30), RDS db.t4g.small Multi-AZ (~75), ElastiCache cache.t4g.micro (~12), CloudFront + WAF (~15), Secrets Manager, KMS, CloudWatch, Route 53 (~25), Business support if enabled (100 minimum). **Set a budget alarm before step 1, and destroy everything at the end.** Working through the project over a weekend costs a few dollars.
:::

## Steps

### 0. Guardrails first

Create the budget and alarm (Part VII chapter 4) at 50 USD and 150 USD with email notifications. Enable CloudTrail (one multi-Region trail to an S3 bucket) and GuardDuty. Confirm you are working with Identity Center short-lived credentials (`aws sts get-caller-identity` shows an assumed role).

### 1. Terraform foundations

Repository layout from Part X chapter 10: `infra/modules/{network,postgres,redis,ecs-service,edge,observability}` and `infra/envs/production`. State backend: S3 bucket with versioning, KMS, lockfile; created once by a tiny bootstrap configuration with local state that you then migrate.

Apply in order (separate root modules or targeted applies): network (VPC, 2 public + 2 private subnets, IGW, one NAT, route tables, endpoints), then data (RDS, ElastiCache, Secrets Manager secrets, KMS), then compute (ECR, ECS cluster, task definition, service, ALB, target groups, CodeDeploy app and deployment group, IAM roles), then edge (ACM certificates, CloudFront, WAF, Route 53 records), then observability (alarms, dashboard, SNS topic).

Key snippets beyond those in Part VII and Part X:

```hcl
# ALB listener rule: accept only traffic from CloudFront carrying the shared header
resource "aws_lb_listener_rule" "from_cloudfront" {
  listener_arn = aws_lb_listener.https.arn
  priority     = 10
  action { type = "forward"; target_group_arn = aws_lb_target_group.blue.arn }
  condition {
    http_header {
      http_header_name = "X-Origin-Verify"
      values           = [random_password.origin_verify.result]
    }
  }
  lifecycle { ignore_changes = [action] }   # CodeDeploy swaps target groups
}
resource "aws_lb_listener" "https" {
  load_balancer_arn = aws_lb.main.arn
  port              = 443
  protocol          = "HTTPS"
  ssl_policy        = "ELBSecurityPolicy-TLS13-1-2-2021-06"
  certificate_arn   = aws_acm_certificate_validation.regional.certificate_arn
  default_action { type = "fixed-response"; fixed_response { content_type = "text/plain"; message_body = "forbidden"; status_code = "403" } }
}

# Task definition: secrets injected by ECS from Secrets Manager; nothing in plain environment
resource "aws_ecs_task_definition" "api" {
  family                   = "portal-api"
  cpu                      = 512
  memory                   = 1024
  network_mode             = "awsvpc"
  requires_compatibilities = ["FARGATE"]
  execution_role_arn       = aws_iam_role.execution.arn
  task_role_arn            = aws_iam_role.task.arn
  runtime_platform { cpu_architecture = "ARM64"; operating_system_family = "LINUX" }
  container_definitions = jsonencode([{
    name  = "api"
    image = var.image            # registry/portal-api@sha256:...
    portMappings = [{ containerPort = 8080, protocol = "tcp" }]
    readonlyRootFilesystem = true
    linuxParameters = { initProcessEnabled = true }
    environment = [{ name = "APP_ENV", value = "production" }, { name = "OTEL_EXPORTER_OTLP_ENDPOINT", value = "http://localhost:4317" }]
    secrets = [
      { name = "DATABASE_URL", valueFrom = aws_secretsmanager_secret.database_url.arn },
      { name = "REDIS_AUTH",   valueFrom = aws_secretsmanager_secret.redis_auth.arn }
    ]
    healthCheck = { command = ["CMD", "/venv/bin/python", "-c", "import urllib.request,sys; sys.exit(0 if urllib.request.urlopen('http://127.0.0.1:8080/health', timeout=2).status==200 else 1)"], interval = 10, timeout = 3, retries = 3, startPeriod = 20 }
    logConfiguration = { logDriver = "awslogs", options = { "awslogs-group" = aws_cloudwatch_log_group.api.name, "awslogs-region" = var.region, "awslogs-stream-prefix" = "api" } }
  }])
```

### 2. Push the image

Add an ECR repository (immutable tags, scan on push, KMS) and extend the Project 3 pipeline to push there via an OIDC role bound to your repository's `main` branch. Deploy by digest.

### 3. Migrations and first deploy

Run migrations as a one-off task (Part X chapter 8 snippet) using a migration secret with the owner role. Then create the ECS service with the blue target group and run the CodeDeploy deployment group with `CodeDeployDefault.ECSCanary10Percent5Minutes`, alarms attached for automatic rollback.

### 4. Edge

ACM certificate in `us-east-1` for CloudFront and a regional one for the ALB (DNS validation via Route 53). CloudFront distribution with the ALB origin, the `X-Origin-Verify` custom header, TLS 1.2+ viewer policy, a cache policy that forwards authorisation headers and does not cache API responses, and the WAF web ACL (AWS managed common rules, known bad inputs, IP reputation, a rate rule of 1,000 requests per 5 minutes per IP). Route 53 alias record for `api.yourdomain.example` to the distribution.

### 5. Observability

Alarms: ALB 5xx ratio (Part XI chapter 3 snippet), target response time p95 > 1 s, unhealthy host count > 0, RDS CPU > 80% for 15 min, RDS FreeStorageSpace < 20%, DatabaseConnections > 80% of max, ECS running tasks < desired, and a composite alarm for "service degraded". SNS topic with email subscription. A dashboard with the golden signals and a log insights query widget for errors.

### 6. Pipeline

Wire `deploy.yml` from Part X chapter 10: build → verify signature → migrate → deploy via CodeDeploy → smoke test → deployment record to an object-locked bucket. Protect the `production` environment with a required reviewer (yourself on a second account, or a teammate).

## Operate it

1. **Deploy a change** (change a response header) through the pipeline; watch the canary shift in the CodeDeploy console.
2. **Break it**: deploy a version whose `/health` returns 500 after 60 seconds; confirm CodeDeploy rolls back automatically on the alarm and the deployment record says so.
3. **Roll back manually**: redeploy the previous digest via `workflow_dispatch`.
4. **Restore**: restore the RDS instance to a point in time 30 minutes ago as a new instance; connect from a one-off task; verify data; delete the restored instance.
5. **Rotate**: trigger rotation of the database secret; confirm tasks pick up the new credential (ECS injects at task start, so a rolling restart is needed: plan for it in the rotation runbook).
6. **Scale**: set a target-tracking autoscaling policy on ALB request count per target; load test with k6 from your machine (modest, within your budget) and watch tasks scale.
7. **Cost**: after 48 hours, open Cost Explorer grouped by service; compare with your estimate; note NAT and ALB as fixed costs.

## Verification

```checklist
# Project 4 verification
- https://api.yourdomain.example/health returns 200 via CloudFront; the ALB DNS name directly returns 403 (origin verify header enforced)
- All tasks in private subnets; RDS and Redis not publicly accessible; security groups reference SGs, not CIDRs
- No long-lived AWS keys anywhere: pipeline roles assumed via OIDC; your access via Identity Center
- Secrets appear only in Secrets Manager; the task definition references ARNs; CloudTrail shows GetSecretValue by the execution role only
- RDS: encrypted, Multi-AZ, deletion protection, 7-day PITR; a PITR restore was performed
- CodeDeploy automatic rollback demonstrated; manual rollback by digest demonstrated
- Alarms fire to your email during the broken deploy; budget alarm configured
- WAF blocks a request containing a basic SQL injection payload in the query string (403 from CloudFront)
- terraform plan shows no drift after all operations
- Cost Explorer shows spend consistent with the estimate; NAT and ALB are the largest fixed lines
```

## Security checks

Run Prowler against the account and address findings in your resources (expect flags on the ALB access logs bucket policy, ECR scan settings, log retention). Confirm GuardDuty has no findings. Run `aws accessanalyzer` (IAM Access Analyzer) for the account and confirm no unintended external access. Check the task role has only the actions the app needs (Secrets Manager read of its two secrets, CloudWatch logs, nothing else).

## Troubleshooting

- **Tasks fail to start with "ResourceInitializationError: unable to pull secrets"**: execution role lacks `secretsmanager:GetSecretValue` and `kms:Decrypt`, or the Secrets Manager VPC endpoint is missing and there is no NAT route.
- **Target group unhealthy**: security group from ALB to task port missing; health path wrong; container listening on 127.0.0.1 instead of 0.0.0.0 (in Fargate the container must bind all interfaces inside the task).
- **CloudFront 502**: origin protocol/SSL mismatch or the ALB certificate's name does not match the origin domain name.
- **CodeDeploy stuck**: test listener or second target group misconfigured; check the deployment events.
- **Terraform wants to replace the RDS instance**: an attribute change forcing replacement; `prevent_destroy` blocks it; read why before changing anything.

## Cleanup

Reverse order: edge, compute, data (disable deletion protection first and take a final snapshot if you want to keep data), network. `terraform destroy` per root module. Then: delete the ECR images, empty and delete the log and access-log buckets (versioned buckets need all versions removed), delete the state bucket last, remove the Route 53 records, release any Elastic IPs, and check Cost Explorer the next day for stragglers (NAT Gateways and ALBs are the usual leftovers).
