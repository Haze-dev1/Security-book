# Project 2: Production-Ready Backend

:::objectives
- Build a small but complete backend API (authentication, authorisation, a resource with ownership, pagination, idempotent writes) with the production properties this handbook demands: structured logging, metrics, tracing, health checks, configuration validation, migrations, tests, rate limiting and security headers.
- Measure it against the production readiness checklist and fix what fails.
:::

:::prereq
Parts III, IV and VIII; [Logs, Metrics and Traces](#/p11/c01); [Testing Strategies](#/p12/c05). Tooling: Python 3.12 (or Node 22), Docker for PostgreSQL and Redis locally.
:::

:::cost Estimated cost
Zero: everything runs locally in containers.
:::

## What you will build

A "documents" API for a client portal: users belong to an organisation; they can create, list, read, update and delete documents in their organisation; admins can manage users. Authentication via OIDC tokens from a local Keycloak (or a signed-JWT test issuer); authorisation by role and resource ownership; every write accepts an `Idempotency-Key`.

## Steps

### 1. Skeleton and configuration

Create the project with a `config/schema.yaml` (Part XIII chapter 10) and startup validation: `DATABASE_URL_SECRET` or `DATABASE_URL`, `REDIS_URL`, `OIDC_ISSUER`, `OIDC_AUDIENCE`, `APP_ENV`, `LOG_LEVEL`, `RATE_LIMIT_PER_MINUTE`. Fail fast on missing keys. Commit a `docker-compose.yml` with PostgreSQL 16, Redis 7, Keycloak (dev mode), the OTel Collector, Jaeger, Prometheus and Grafana.

### 2. Data model and migrations

```sql
-- migrations/0001_init.sql
CREATE TABLE organisations (id uuid PRIMARY KEY, name text NOT NULL, created_at timestamptz NOT NULL DEFAULT now());
CREATE TABLE users (id uuid PRIMARY KEY, org_id uuid NOT NULL REFERENCES organisations(id), subject text UNIQUE NOT NULL, email text NOT NULL, role text NOT NULL CHECK (role IN ('member','admin')), created_at timestamptz NOT NULL DEFAULT now());
CREATE TABLE documents (
  id uuid PRIMARY KEY, org_id uuid NOT NULL REFERENCES organisations(id), owner_id uuid NOT NULL REFERENCES users(id),
  title text NOT NULL CHECK (length(title) BETWEEN 1 AND 200), body text NOT NULL CHECK (length(body) <= 100000),
  created_at timestamptz NOT NULL DEFAULT now(), updated_at timestamptz NOT NULL DEFAULT now(), deleted_at timestamptz
);
CREATE INDEX documents_org_created_idx ON documents (org_id, created_at DESC, id DESC) WHERE deleted_at IS NULL;

ALTER TABLE documents ENABLE ROW LEVEL SECURITY;
ALTER TABLE documents FORCE ROW LEVEL SECURITY;
CREATE POLICY documents_tenant ON documents
  USING (org_id = current_setting('app.org_id', true)::uuid)
  WITH CHECK (org_id = current_setting('app.org_id', true)::uuid);
-- Application role cannot bypass RLS
CREATE ROLE app_rw LOGIN PASSWORD 'dev-only';
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_rw;
```

Use a migration tool; the app role must differ from the migration role.

### 3. Middleware chain

Implement, in order: request ID (accept `X-Request-ID` or generate; echo in response); structured JSON logging with request ID, trace ID, route template, status, duration; Prometheus metrics (RED with templated routes); OpenTelemetry auto-instrumentation; authentication (validate JWT against cached JWKS, check `iss`, `aud`, `exp`, algorithm allowlist; map subject to user and organisation; set the tenant context); rate limiting (token bucket in Redis per user and per IP, `429` with `Retry-After`); security headers; a global error handler that returns RFC 9457 problem details without stack traces.

```python
# Tenant context into the database session, per transaction
@contextmanager
def tenant_tx(pool, org_id: UUID):
    with pool.connection() as conn, conn.transaction():
        conn.execute("SELECT set_config('app.org_id', %s, true)", (str(org_id),))
        yield conn
```

### 4. Routes

`GET /documents?cursor=&limit=` (keyset pagination on `(created_at, id)`, max limit 100), `POST /documents` (requires `Idempotency-Key`; store key → response in Redis with the request hash; replay returns the stored response; mismatch returns `422`), `GET /documents/{id}` (404 for other orgs or deleted), `PATCH /documents/{id}` (owner or admin), `DELETE /documents/{id}` (soft delete; owner or admin), `GET /admin/users` and `POST /admin/users` (admin only). `GET /health` (liveness), `GET /ready` (DB and Redis bounded checks), `GET /metrics` (restricted to internal network in production), `GET /openapi.json`.

### 5. Observability

Logging: no PII (log `user_id`, never email); redaction of `Authorization`. Metrics: `http_requests_total`, `http_request_duration_seconds`, `db_pool_in_use`, `rate_limit_rejections_total`, `idempotency_replays_total`. Traces: spans for DB queries (instrumented driver) and a business span `documents.create`. Build a Grafana dashboard with RED panels, pool usage and a link from a latency panel to Jaeger.

### 6. Tests

Unit tests for pagination cursors, idempotency hashing and token validation (expired, wrong audience, wrong algorithm, `alg: none`). Integration tests with Testcontainers for: RLS (a query without context returns nothing; with org A context cannot see org B rows), the cross-tenant matrix (every endpoint as A against B's IDs → 404), idempotent create (same key twice → one row, same response), concurrent creates with the same key (exactly one row), rate limiting (N+1th request → 429), soft delete invisibility. A contract test validating responses against the OpenAPI document.

### 7. Hardening pass

Dependency scan (`pip-audit`/`npm audit`), SAST (Semgrep OWASP rules), container image built multi-stage non-root, `.dockerignore`, secrets only via environment or files, request body size limit, JSON depth limit, strict content-type checks, CORS allowlist if a browser client exists, cookie flags if sessions are used, `X-Content-Type-Options`, `Referrer-Policy`, `Content-Security-Policy` for any HTML.

## Verification

```checklist
# Project 2 verification
- Starting with a missing required config key exits non-zero with a clear message
- An expired token, a token with the wrong audience, and a token signed with a different key are all rejected with 401 and no stack trace
- The cross-tenant test matrix passes; a direct SQL query as the app role without app.org_id set returns zero rows
- Two POSTs with the same Idempotency-Key create one document and return identical responses; a different body with the same key returns 422
- 50 concurrent POSTs with one key create exactly one row
- Requests beyond the rate limit get 429 with Retry-After; the metric increments
- Every log line is JSON with request_id and trace_id; no email addresses appear in a day of test logs
- A trace in Jaeger shows the HTTP span with child DB spans; the Grafana dashboard shows p95 per route
- /ready returns 503 within 1 s when PostgreSQL is stopped; /health keeps returning 200
- Image scan reports no critical/high fixable vulnerabilities; container runs as non-root
```

## Security checks

Run OWASP ZAP baseline against the running API; confirm no high findings. Attempt mass assignment (`{"org_id": "<other>"}` in POST) and confirm it is ignored or rejected. Attempt a 10 MB body and confirm `413`. Attempt a JWT with `alg: none` and `kid` pointing to an arbitrary URL; confirm rejection. Confirm `/metrics` is not reachable from the public port in the production compose profile.

## Troubleshooting

- **RLS returns nothing even with context set**: `set_config` with `is_local = true` applies to the transaction; make sure the query runs in the same transaction; check `FORCE ROW LEVEL SECURITY` and that you are not connected as the table owner.
- **Traces missing DB spans**: the driver instrumentation must be installed before the pool is created.
- **Idempotency race**: use `SET NX` on the key with a short "in-progress" marker before processing; a concurrent request seeing the marker waits or returns 409.
- **Rate limit inconsistent**: clock skew between app instances if using fixed windows; use Redis-side token buckets with a Lua script.
